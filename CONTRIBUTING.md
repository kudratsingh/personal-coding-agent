# Contributing

Thanks for contributing. This project is at its foundation stage, so small, well-tested improvements are especially valuable.

## Before opening a pull request

1. Start from the current public roadmap and choose one focused change.
2. Keep private plans, credentials, datasets, weights, logs, and artifacts out of the branch.
3. Add or update tests when behavior changes.
4. Explain the purpose, verification, and any follow-up work in the pull request.

## Development expectations

Core components should have a simple reference test where practical. Changes that introduce a new data source, external service, paid compute, or public performance claim need maintainer approval before merge.

## Reporting issues

Use the issue templates for bugs and features. For security concerns, follow [SECURITY.md](SECURITY.md) instead of opening a public issue.
