The [current review](real-samples.md) joins every sample file to The Stack dedup v1.2 `max_stars_repo_licenses` on its exact repository and path, and retains **82.80882% of Python text bytes** (**190,222 files / 828,088,405 bytes**), up from **12.27013%**. Explicit copyleft, restricted and unrecognized headers, off-allowlist repository licenses and quality/contamination drops remain separate classes. Encoding the retained selection with the frozen tokenizer gives **198,273,119 tokens / 828,088,405 bytes**, or **4.1765036490 bytes/token**, excluding BOS. This recount fits no tokenizer; the 2026-10-20 count of 26,328,493 tokens covered only the header-licensed subset.

Extrapolating that ordered-prefix policy to **64,000,000,000 raw text bytes** yields **12,689,476,748 tokens**, or **12,626,029,364 after a 0.5% validation reserve**, excluding BOS; the 2026-10-20 forecast was **1,685,023,171 / 1,676,598,055**. This is a conditional forecast from one shard's ordered prefix, not a full-source token count or a guarantee of unique usable tokens. Under it, each model's Python target fits inside the 59 available StarCoderData Python containers: the selected S rehearsal's 0.9B tokens need **4.56GB** of raw Python text from **5** containers, the optional larger S target of 1.8B needs **9.12GB** from **9**, M's 4.5B needs **22.81GB** from **22**, and L's 8.1B needs **41.06GB** from **40**. Before the recovery, the optional larger S target, M and L exceeded the source (**66, 164 and 295** containers needed of 59). No new source, repeat epoch or rights relaxation is assumed beyond the owner's D-05 corrections for ISC, Unlicense, 0BSD and WTFPL. The small rehearsal's full build still waits for review.

Two caveats bound this forecast. A license mapping exists only for the **209,914** sampled files; a full build first needs an owner-authorized metadata read for every container it uses, and the forecast assumes the join keeps the sample's match rate there. The 64GB source size is the plan's approximation; 59 Python containers at the container-0 text proxy of 1,049,067,107 bytes each come to about **61.9GB**, which would lower the token figures by about 3%.

Task-source retention/context fit remain assumptions, with **0 final trained-pool admissions**. Local pinned-isolation timing now covers **80 partition calls across 40 cached tasks**, using four workers; source means are approximately **0.83 seconds/partition** including launch/execution/cleanup. These short ordered prefixes are not representative throughput bounds, and AceCode/TACO are not measured. The private capped-rehearsal table labels proxies and unknown easy counts explicitly. Final holdouts, component rights and production-host approval remain unresolved. Tokenization time alone is not full-build time.
