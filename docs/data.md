# Data policy

Training sources must have verified licenses and documented provenance before use. An aggregate dataset description is not a substitute for checking its individual components and source terms.

For each source record its identifier, pinned revision, purpose, license and attribution, terms acceptance where required, content hash, and transformation steps. Use synthetic or redistributable fixtures for automated tests.

Keep benchmark prompts, reference solutions, hidden tests, and held-out tasks out of every training stage. Apply duplicate and contamination checks before splitting; make splits deterministic and record their hashes.

Raw corpora, tokenized shards, and credentials remain outside Git. Publish a data card listing the sources actually used when a training milestone is released. No production training dataset is currently included or approved by this starter.

The [current data card](data-card.md) records synthetic development fixtures and the separate evaluation-only HumanEval reference. The manifest downloader fails closed on missing approval, unpinned revisions, disallowed training licenses, absent gated terms acceptance, or mismatched bytes.

Manifest validation happens before creating a download directory, consuming supplied chunks or opening the network. Provenance fields must be nonempty strings; review/terms flags must be actual booleans (`"false"` and `1` are not accepted as approvals), and byte counts must be nonnegative integers rather than booleans or floats. Source URLs require HTTPS, a host and no inline username/password; optional terms dates must be valid, nonfuture `YYYY-MM-DD` values. These checks validate the record's shape, not its truth: a `license_verified` flag never substitutes for primary-source review or the owner's required terms acceptance. The training-license allowlist and evaluation-only separation are unchanged.

The downloader hashes bounded streamed bytes into a temporary file, checks the exact declared size and SHA-256, and publishes only a matching complete file. Authored tests in `tests/test_manifest.py` prove malformed records fail before filesystem/network access and mismatched downloads preserve existing destination data. They use synthetic bytes, not external corpora or credentials.

Each network redirect must also satisfy the HTTPS/host/no-inline-credentials URL policy. Relative redirects and HTTPS CDN hosts remain supported; HTTP downgrades fail before the next target opens. The downloader uses its own opener rather than changing global HTTP behavior, retains the standard redirect-loop limit and closes rejected/error responses. `tests/test_download_redirects.py` exercises real urllib redirect processing through an entirely authored offline transport, including multi-hop rejection and destination preservation. This is a transport restriction, not a host allowlist, network sandbox, license approval or publisher authentication.

Filtering records a primary rejection reason per source for length, code shape, generated markers, exact duplicates, and held-out n-gram matches. The default contamination index uses normalized 13-word sequences from supplied held-out text. This catches planted verbatim spans, not every paraphrase; real corpora still need further review and near-duplicate analysis. Document hash splits are deterministic and keep stage-1, stage-2, and validation web material separate.

Token shards store little-endian uint16 IDs with an explicit BOS at every document start, document offsets, a tokenizer hash, and content integrity hash. The reader validates header types, declared vocabulary, offsets and each decoded document's token range. New headers record BOS; legacy identities remain unchanged, with missing BOS checked only when explicit tokenizer context is available. Training/validation require the actual tokenizer's vocabulary/BOS expectations. See the [shard walkthrough](walkthroughs/shards.md). The loader reads documents on demand, partitions document indices across ranks, mixes fixed-length sequences by source share, and serializes RNG/buffer/position state for exact resume. Supply separate, decontaminated source/split shard sets; the loader cannot infer provenance from token IDs.

Normalized task JSONL keeps prompt/public tests separate from hidden tests and optional reference solutions. Source adapters require explicit field mappings; real-source schemas are verified when ingestion is approved, not guessed from dataset names. Pool admission rejects benchmark IDs, prompt near-duplicates, contaminated spans, and references that fail either test partition. Missing isolation aborts admission. Assign held-out sizes after deduplication and preserve immutable upstream holdouts.

Conservative reviewed-schema adapters cover OpenCodeInstruct assertion lists, AceCode recorded completions, full MBPP rows, and evaluation-only HumanEval rows. They require a validated provenance entry, preserve source revision, canonicalize MBPP benchmark IDs, and reject unsupported test statements instead of executing source setup on the host. Passing upstream attempts still require local isolated verification. Other source variants and full-corpus admission remain separate ingestion work.

`adapt_taco_io_row` supports only the explicitly documented EASY standalone text/stdin/stdout subset. It parses solution/test JSON without executing source metadata, requires the original split, prevents upstream test rows and evaluation-only provenance from becoming training data, and rejects function/image/ambiguous/unsupported cases. Duplicate inputs are removed before public/hidden partitioning; conflicting expected outputs fail. A candidate solution is still untrusted until sandbox verification. This restricted adapter is not full TACO coverage or approval of upstream component rights. Pool reports include per-source seen/kept/drop counters; `split_summary` reports source and human/model counts per assigned split.

The adapter follows the [pinned upstream schema description](https://huggingface.co/datasets/BAAI/TACO/blob/d593ed0a2becbbc952230bb89be09189bf1056dc/README.md), not its metadata-execution examples. Fixed upstream holdouts are never demoted to satisfy requested split sizes: an oversubscribed request fails explicitly. Unknown isolation outcomes also abort admission. A brute-force Jaccard reference test checks the near-duplicate index's prefix candidate filter.
